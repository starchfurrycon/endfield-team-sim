## 0. 产品定义（一句话）

用户输入「必须包含 / 禁止包含 / 可选池 / 敌人场景」→ 输出
**Top-N 配队**，每队给出 **冷启动轴（终结技能量 0）** 与 **热启动轴（终结技能量满）**，
并附**可解释理由 + 置信度 + 未建模项清单**。

---

## 1. 设计原则（不可协商）

1. **数值必须可溯源**：每个数字带 `source`（表名/字段/URL）与 `confidence`。
2. **LLM 不产出数值**：只产出语义标签、分类、解释文本。数值一律来自数据表。
3. **未知必须可见**：未建模的乘区、猜测的常量，写进结果的 `warnings` / `unmodeled`。
4. **失败不覆盖**：同步失败时保留上一版数据集，并显式报错。
5. **可离线运行**：所有网络数据都有本地缓存；无 LLM key 时功能降级但不崩溃。
6. **排序优先于绝对值**：产品卖点是“哪个队/哪条轴更好”，不是“打出多少伤害”。

### 2.2 核心数据模型（`model.py`）

```python
Skill      : skill_id, slot(普攻/战技/连携/终结/下落/处决/冲刺), name_zh, element,
             levels[12] -> LevelRow(multipliers{key:value}, cost, cooldown, energy),
             timing: Timing(duration_frames, exclusive_frames, offset_frames, hit_frames[]),
             semantics: Semantics(trigger, applies, gains, targets, duration_s, tags)
Operator   : char_id, name_zh, rarity, profession, element, weapon_type,
             main_attr, sub_attr, stats_curve{1..90}, talents[], potentials[],
             skills{slot: Skill}, semantics_coverage
Timing     : 全部整数帧 @30fps（唯一时间单位）
Scenario   : team[4], enemy(poise, def, res, hp, attack_timeline[]), duration_s,
             start_energy(0|max), weapon_assumption, seed
Result     : timeline rows, total_damage, dps, per_operator, sp_events,
             energy_events, warnings[], unmodeled[], legality_ok
```

**时间单位统一为帧（1 帧 = 1/30 s）**，所有 UI 输出再换算成秒。

### 2.3 关键机制建模决策（写死，别改）

| 机制 | 建模方式 | 依据 |
|---|---|---|
| 动作可取消 | 承诺 `exclusiveFrame` 帧，之后可切动作；不切则跑到 `durationFrame` | SkillData 字段语义 |
| 普攻连段 | `attack1..attackN` 顺序，N 由数据中存在性决定（3–5 段）；第 N 段即**重击**，回复技力 | SkillData + Wiki |
| 技力 | 全队共享 0–300，每技能 `costValue`（通常 100）；重击/完美闪避/处决回复 | SkillPatchTable |
| 终结技 | 每人独立 0–`所需终结技能量`，成本 `costType=0`；战技/连携充能 | SkillPatchTable |
| 连携技 | 触发条件来自语义层；窗口 5s；冷却来自表 | Wiki + 表 |
| 受击 | 敌人攻击时间表（场景输入）命中主控 → 触发 `on_hit_taken` 条件 | 显式输入，不猜 |
| 元素/异常 | 状态机：附着→爆发→异常；物理异常 破防/消耗 两段 | Wiki 机制页 |
| 伤害 | 只接地的乘区参与，其余列 `unmodeled` | §1 原则 3 |
| 切换主控 | 固定开销 `SWITCH_FRAMES`（配置，默认估计值，标注 estimate） | 无数据，显式假设 |

### 2.4 配置与常量（`config.py`）

所有猜测常量集中在一处，带 `source: "estimate"`，并在输出里列出：
`SWITCH_FRAMES`, `SP_REGEN_PER_SEC`, `SP_GAIN_HEAVY`, `SP_GAIN_PERFECT_DODGE`,
`ULT_ENERGY_PER_BATTLE_SKILL`, `ULT_ENERGY_PER_COMBO`, `COMBO_WINDOW_FRAMES`,
`ENEMY_DEFAULT_POISE/DEF/RES`, `CRIT_RATE_BASE=0.05`, `CRIT_DMG_BASE=0.5`.

## 3. 阶段拆解与交付物

### P0 · 数据基座（先做，做扎实）

- [ ] `sources.py`：登记 2 个 GitHub 源 + BWIKI，记录 `ref`（commit sha / revid）与许可说明。
- [ ] `http.py`：统一请求（UA、超时、重试、ETag/内容哈希缓存、限速）。
- [ ] `github.py`：拉 `TableCfg/{CharacterTable,SkillPatchTable,BattleConst,AttributeMetaTable,CharacterTable}` +
      按需拉 `Json/SkillData/<id>.json`（只拉需要的，不整仓克隆）。
- [ ] `wiki.py`：`action=ask` 干员索引、`MediaWiki:Skilldata.json`、干员页 wikitext、`/详细数据`。
- [ ] `build.py`：raw → `operators/*.json` + `dataset.json`；字段带 `source`。
- [ ] `coverage.py`：覆盖率报告（数据齐全 / 缺帧 / 缺语义 / 缺 Wiki 页）。
- [ ] `manifest.json`：源版本、拉取时间、文件哈希、数据集版本号。
- [ ] `endfield sync` / `endfield build` / `endfield check`。

**验收**：断网可重跑 `build`；`check` 输出覆盖率；任一源失败不破坏既有数据集；
数据与 Wiki `Skilldata.json` 的倍率抽样比对一致率 100%（同版本）。

### P1 · 语义层（让文本变得可执行）

> **v2.5.0 增补**：P1 的 LLM 通道从"可选骨架"升级为可用的自更新通道
> （用户自带 API、提示词资产化、证据校验、复核报告）。
> 变更记录见 [`03-进展.md`](03-进展.md) 的「追加轮十一」。


- [ ] `rules.py`：从技能描述抽取
      `element_apply`、`abnormal`、`trigger`（受击/重击/闪避/处决/治疗/切换/技能命中/状态命中）、
      `target`（自身/全队/单体/范围）、`duration_s`、`gains`（技力/能量）、`is_dot`、`needs_enemy_hit`。
- [ ] `schema.py`：JSON Schema 校验（枚举封闭，未知值必须落 `unknown`，不许静默丢弃）。
- [ ] `llm.py`：可选增强；输入=技能文本+槽位，输出=同 schema；**校验失败即丢弃**；
      内容寻址缓存 `data/llm/<sha>.json`；`--no-llm` 强制离线。
- [ ] 分歧报告：规则 vs LLM 不一致的条目 → `data/reports/semantics-divergence.md`。

**验收**：全部干员 × 全部技能都有语义对象（允许 `unknown`）；`unknown` 占比 < 15%；
受击类技能 100% 被标记（用户点名的依赖）。

### P2 · 仿真引擎

- [ ] `timeline.py`：整数帧事件循环；`ActionInstance` 生命周期；取消/排队规则。
- [ ] `state.py`：SP、能量、冷却、连携窗口、失衡、元素状态、buff（最小集）。
- [ ] `actions.py`：动作目录（普攻链/战技/连携/终结/闪避/处决/待机），合法性判定。
- [ ] `damage.py`：公式分层 + 乘区开关 + 缩放与四舍五入。
- [ ] `simulate.py`：给定 `Scenario + Rotation` → `Result`（含逐帧 timeline 与事件流）。
- [ ] 不变量检查：技力不为负、冷却不放行、能量不超上限、同一角色不同时两个动作。

**验收**：全干员随机 1000 条合法/非法轴跑完不崩；不变量 0 违反；同输入可复现（种子）。

### P3 · 搜索

- [ ] `rotations.py`：beam search（状态=时间+SP+能量+冷却+失衡，动作=合法动作集合），
      目标函数 = 窗口内伤害（可配置加权：伤害/失衡/充能）。
- [ ] 冷启动（能量 0）/ 热启动（能量满）两种初始条件分别搜索。
- [ ] `teams.py`：约束求解（必须/禁止/池大小/主控候选）→ 候选队 → 每队跑轴搜索 → 排序。
- [ ] 剪枝：同质队去重、时间预算、早停。

**验收**：任意约束下 60s 内给出 Top-5；每队都附冷/热两条轴；结果可复现。

### P4 · 表达层

- [ ] `explain.py`：离线模板解释（为什么这个队/这条轴），可选 LLM 润色。
- [ ] `cli.py`：`sync / build / check / axis / team / explain / audit`。
- [ ] 输出 JSON + 人读 Markdown 双格式。

**验收**：CLI 一条命令跑通全流程；Markdown 报告可直接给人看。

### P5 · 验证与文档

- [ ] `tests/`：公式单测、时间轴单测、不变量、语义 schema、端到端 smoke。
- [ ] `docs/03-进展.md`：每阶段记录 + 偏离计划说明。
- [ ] `README.md`：安装、用法、**能力边界与免责**。

**验收**：`python -m pytest` 全绿；`tools/run_demo.py` 稳定产出示例。
